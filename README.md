# fnos-nas-agent

A lightweight, self-hosted Agent for Feiniu OS (fnOS) NAS, designed around a mobile-friendly LAN web interface, controlled NAS operations, and a reviewable Skill manager.

> **Status: specification phase.** The current branch contains design and security documents only. No NAS commands are executed by this repository, and no FPK has been built.

## Goals

- Replace a heavier general-purpose Agent with a small Node.js-native service.
- Support a phone-friendly web console and command-line maintenance entry point.
- Prefer deterministic rules for common read-only requests; use a remote model API only when needed.
- Import, inspect, approve, enable, disable, update, and remove Skills without executing imported code during review.
- Require explicit confirmation for risky operations; deny destructive actions by default.
- Keep API keys, OAuth tokens, passwords, and sensitive output out of source control and logs.
- Package as an fnOS FPK after validating the current official packaging requirements.

## Planned first capability

The supplied official fnOS Skill package is the first integration candidate. It documents using `trim-cli` and an OAuth 2.0 Authorization Code + PKCE flow. Its exact command syntax, platform support, token handling, and permission requirements must be checked against the package before implementation. The Skill's own instructions are not permission to run arbitrary commands.

## Architecture at a glance

- `src/agent/` — task coordination and bounded plans
- `src/skills/` — Skill import, review, lifecycle, and inventory
- `src/adapters/fnos/` — fixed allowlist of fnOS operations
- `src/policy/` — risk tiers, approvals, and read-only mode
- `src/web/` — mobile-first web UI and HTTP API
- `packaging/fpk/` — FPK files, to be added after format verification
- `docs/` — architecture, security, Skill lifecycle, development, and tool mapping

## Development principles

1. Do not develop against the production NAS.
2. No arbitrary shell commands generated by a model.
3. Imported Skills remain inert until reviewed; v0.1 does not execute arbitrary Skill code.
4. Read-only tools first; mutations require an explicit policy decision and confirmation.
5. Bound time, concurrency, request size, and output size.
6. Verify the official fnOS FPK format before writing packaging lifecycle files.
7. Test failure paths and security boundaries before enabling the adapter.

## Roadmap

1. **Specification** — define architecture, risk tiers, Skill lifecycle, and tool contracts.
2. **Core skeleton** — minimal Node.js HTTP service, mobile UI, configuration, and tests.
3. **Skill manager** — safe ZIP import, quarantine, inventory, hashing, review, and lifecycle.
4. **fnOS adapter** — implement a small set of verified read-only operations.
5. **Model adapter** — structured plans, schema validation, bounded retries, and token-saving routing.
6. **FPK packaging** — validate install/start/stop/upgrade/uninstall on a test fnOS system.
