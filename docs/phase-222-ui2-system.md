# Phase 222 — UI2 系统区（UI-4）

> 承接旧「诊断与运维」单页堆叠的 13 组能力，按域重组为七个子页签。

## 结构（`ui/next/js/pages/system.js`）

概览（快照/设备档案/健康检查/更新检查）· 网络与证书（诊断/策略/接口/巡检/证书体检）·
容器与服务（服务状态/容器统计/Docker 建议）· 存储健康（SMART/温度/容量预测/系统事件）·
自动化（工作流/MCP/运行手册+统计/触发规则评估）· 审计与轨迹（审计/工具轨迹/待确认写动作）·
诊断报告（历史/统计/一键报告/证据抽取/日志证据/部署校验/组合校验）。

## 实现方式

- 通用「分区引擎」：只读分区 GET + 自动渲染（对象 → kv，数组 → 可折叠列表，标量直出，
  全部经 `formatDisplayValue` 人类可读化）；每个分区独立错误态（501 显示「未启用」）。
- 写侧/计算类动作（巡检、体检、建议、触发评估、证据、部署/组合校验、新建运行手册）：
  JSON 输入（带示例预填）+ 显式按钮，结果以 pre 如实呈现；是否可用由服务端策略裁决，
  界面不重试、不降级（延续 phase-211 原则）。
- 子页签选中态写入 hash（#/system/<id>），刷新后保持。

## 边界

- 本阶段只做「把已有只读面摆上来 + 受控动作入口」，不改任何服务端语义；
- `web-fetch`（默认关闭的网页取证）未放入界面，保持 API-only（与 phase-211 口径一致）。
