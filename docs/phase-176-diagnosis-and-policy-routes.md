# Phase 176 — 诊断历史、写动作登记与网络策略的 HTTP 出口

## 背景

Phase 171–175 交付了五个纯逻辑模块：受控写动作管线（171）、网络策略（172）、
诊断历史（173）、网页证据（175）以及 Phase 174 的观察面板。这些模块本身不联网、
不落盘，但也没有出口，运维依然看不到它们。

本阶段把这些能力接到 HTTP 层，并保持既有安全规则：会话认证、同源校验、只读出口
不写数据、审计记录真实路由名。

## 新增路由

| 路由 | 方法 | 作用 | 风险 |
| --- | --- | --- | --- |
| `/api/diagnoses` | GET | 诊断历史列表（分页） | 只读 |
| `/api/diagnoses/stats` | GET | 诊断历史统计（按结论分组、命中率） | 只读 |
| `/api/diagnoses/:id` | GET | 单条诊断详情 | 只读 |
| `/api/diagnoses/:id/corrections` | POST | 登记一条人工纠正（用于后续相关性统计） | 写入 |
| `/api/write-actions` | GET | 受控写动作登记表（可写动作、所需审批级别） | 只读 |
| `/api/network/policy` | GET | 当前网络策略快照（允许列表、默认判定） | 只读 |
| `/api/network/check` | GET/POST | 对单个 URL 做一次策略判定，不发起请求 | 只读 |
| `/api/web/fetch` | POST | 受控网页抓取，返回网页证据 | 只读（外发） |

## 策略先行的抓取

`POST /api/web/fetch` 的顺序是硬约束：

1. URL 非空校验；
2. `policy.isUrlAllowed(url)` 判定，**不通过就零请求**返回
   `network-url-not-allowed`；
3. 打开整体超时闸门（AbortController）；
4. 发起请求，请求头固定且不含 Cookie / Authorization；
5. 手动跟随重定向，**每一跳重新过策略**；
6. Content-Type 白名单闸门；
7. 按字节上限读取，超限即截断并中止。

默认策略是关闭的，因此该路由在默认配置下只会返回 403，不会建立任何连接。

## 安全边界

- 全部路由需要有效会话，跨源请求被拒。
- `/api/network/check` 只做判定，不发请求。
- 抓取结果不含原始 HTML、响应头与请求头；错误信息里的 URL 凭据被抹除。
- 写动作仍然走既有审批队列，本阶段不新增任何自动写路径。

## 测试

- `tests/phase-176-diagnosis-and-policy-routes.test.mjs`（真实 HTTP 进程）：
  未登录返回 401、跨源返回 403、诊断列表与统计可用、策略快照可用、
  抓取在默认策略下返回 403 且 `evidence` 为空、写动作登记表可读。
- 回归：`tests/phase-171…175` 合计 69 用例全部通过。

## 遗留

- 没有真实外网回归，抓取链路只用注入的假请求验证。
- 未处理 gzip / br 压缩（会被字节上限提前截断）。
- 抓取没有审计落盘，也没有并发与配额控制。
