# FNOS NAS Agent：借鉴腾讯 Marvis 的完整功能清单

> 文档用途：产品规划、功能拆分与开发路线参考。  
> 版本：v1.0  
> 日期：2026-10-22  
> 说明：本文将 Marvis 的通用 AI 助手思路转化为适合飞牛 NAS（FNOS）的产品方案。下列 FNOS 功能是建议设计，不代表当前项目已经实现，也不代表全部属于腾讯 Marvis 已公开的功能。

## 1. 产品定位

建议将 FNOS NAS Agent 建设为系统级 AI 运维与自动化助手，而不是简单的聊天界面。

核心目标：

- 理解用户的自然语言目标。
- 读取真实、可验证的 NAS 系统状态。
- 将复杂任务拆分为多个步骤并调度专业 Agent。
- 通过受控工具执行经过授权的操作。
- 验证执行结果并记录审计信息。
- 通过工作流、定时任务和知识库持续提升自动化能力。

产品核心闭环：

**理解需求 → 收集事实 → 规划任务 → 风险评估 → 用户授权 → 执行操作 → 验证结果 → 记录与总结**

## 2. 优先级定义

- **P0：基础与安全** — 其他能力的前置条件。
- **P1：核心产品能力** — 形成可用的 AI NAS 运维闭环。
- **P2：能力扩展** — 工作流、知识库、文件搜索等。
- **P3：长期进阶** — 预测性运维、多设备管理和高级自动化。

优先级是建议的开发排序，不是当前实现状态。

## 3. 模块 01：主 Agent 与多 Agent 协作

**优先级：P0 基础架构**

| 编号 | 功能 | 具体设计 |
|---|---|---|
| A01 | 自然语言任务理解 | 理解用户目标，不只识别关键词 |
| A02 | 任务自动拆解 | 将“检查 NAS 并修复问题”拆成可执行步骤 |
| A03 | 专业 Agent 调度 | 分派给存储、系统、网络、应用、安全等 Agent |
| A04 | 并行任务执行 | 允许互不依赖的检查并行运行 |
| A05 | 任务依赖管理 | 确保先检查、后修复，先备份、后升级 |
| A06 | 共享任务上下文 | 共享任务 ID、设备状态和执行结果 |
| A07 | 结果汇总 | 汇总多份报告，输出易理解的结论 |
| A08 | 失败重试 | 对可重试错误执行有限次数重试 |
| A09 | 任务恢复 | 服务重启后识别中断任务，并按安全规则恢复 |
| A10 | 任务取消 | 停止排队任务或允许取消的运行任务 |
| A11 | 任务进度展示 | 显示排队、分析、执行、验证、完成或失败 |
| A12 | 任务历史 | 保存步骤、参数、输出和结果 |
| A13 | 任务冲突检测 | 防止多个 Agent 同时修改同一资源 |
| A14 | 成本与资源预算 | 限制模型调用、执行时长和资源消耗 |
| A15 | 计划与执行分离 | 先生成计划，再按风险决定是否执行 |

### 建议的专业 Agent

| Agent | 主要职责 |
|---|---|
| 主 Agent / Planner | 理解目标、规划步骤、调度子 Agent、汇总结果 |
| 存储 Agent | 磁盘、SMART、阵列、容量、共享目录 |
| 系统 Agent | CPU、内存、进程、服务和日志 |
| 网络 Agent | IP、DNS、端口、路由和连通性 |
| 应用 Agent | Docker、容器、镜像、部署和更新 |
| 安全 Agent | 权限、暴露端口、风险与审计 |
| 文件 Agent | 搜索、归档、重复文件和文档解析 |
| 备份 Agent（后续） | 备份状态、完整性和恢复验证 |
| 知识库 Agent（后续） | 检索文档、历史故障与已验证方案 |

**架构原则：Agent 是职责边界，不是安全边界。** 所有 Agent 必须通过统一的工具执行层访问系统，不得因为模型提出命令就直接获得 root 权限。

| S18 | 异常检测 | 发现负载突增、温度异常和反复重启 |

| S20 | 硬件能力评估 | 评估资源能否承载指定服务或模型 |

### 数据可信原则

- 磁盘容量由系统采集接口返回。
- 硬盘健康状态必须有 SMART 或设备健康数据支持。
- 阵列降级必须以真实阵列状态为依据。
- AI 负责解释数据、分析原因、生成建议和组织操作，不得编造系统状态。
- 数据不可用时应明确显示“未知”或“未采集”，不能伪装成正常。

## 5. 模块 03：AI 故障诊断与自动修复

**优先级：P0 / P1**

| 编号 | 功能 | 具体设计 |
|---|---|---|
| D01 | 故障问诊 | 用户描述现象后自动收集相关信息 |
| D02 | 日志关联 | 按时间关联系统、内核和应用日志 |
| D03 | 故障分类 | 区分存储、网络、资源、权限和应用问题 |
| D04 | 根因候选 | 给出可能原因及各自证据 |
| D05 | 置信度说明 | 区分已证实结论和推测 |
| D06 | 修复计划 | 生成分步方案及潜在副作用 |
| D07 | 只读诊断 | 优先执行不改变系统状态的检查 |
| D08 | 一键修复 | 用户确认后执行允许的修复动作 |
| D09 | 修复前检查 | 检查权限、空间、依赖和服务状态 |
| D10 | 修复后验证 | 重新采集指标，判断问题是否解决 |
| D11 | 失败回退 | 对有明确回滚方案的配置操作进行恢复 |
| D12 | 故障报告 | 记录症状、证据、根因、处理步骤和结果 |
| D13 | 历史故障关联 | 比较本次问题与历史同类事件 |
| D14 | 修复知识积累 | 将验证过的解决方案沉淀到知识库 |
| D15 | 自动升级 | 生成可交由人工处理的诊断包 |

### 典型诊断流程

用户：“为什么我的 NAS 今天特别慢？”

1. 检查 CPU、内存、Swap 和系统负载。
2. 检查磁盘延迟、I/O 错误和存储空间。
3. 检查 Docker 容器资源使用和异常重启。
4. 查询与问题时间相关的系统日志。
5. 关联证据并排序可能原因。
6. 输出诊断结论、证据和风险等级。
7. 如需修改服务或系统配置，先请求批准。
8. 执行获准的操作并重新验证。

不能把“重启所有服务”当作通用修复策略。对磁盘故障、阵列降级或数据损坏，贸然操作可能加重损失。

## 10. 模块 08：安全审计与权限控制

**优先级：P0 安全底座**

| 编号 | 功能 | 具体设计 |
|---|---|---|
| SEC01 | 最小权限 | 每个工具只拥有必要权限 |
| SEC02 | 用户身份校验 | 操作前确认身份和权限 |
| SEC03 | 工具权限表 | 明确每个 Agent 可以调用的工具 |
| SEC04 | 风险分级 | 区分只读、低风险、敏感和高风险操作 |
| SEC05 | 高风险确认 | 删除数据、重建阵列等操作需要严格审批 |
| SEC06 | 操作审计 | 记录请求、工具、参数、结果和操作者 |
| SEC07 | 敏感信息保护 | 防止密钥、令牌和密码进入普通日志 |
| SEC08 | 命令注入防护 | 禁止不受控的字符串拼接和任意 shell 执行 |
| SEC09 | 路径访问约束 | 限制文件操作根目录，防止路径穿越 |
| SEC10 | 权限绕过防护 | 服务端再次验证资源访问权限 |
| SEC11 | 提示词注入防护 | 将文件、网页和日志视为不可信输入 |
| SEC12 | 删除保护 | 展示删除对象、数量和影响范围 |
| SEC13 | 备份前置检查 | 关键变更前确认备份可用性 |
| SEC14 | 回滚策略 | 明确是否可回滚及具体步骤 |
| SEC15 | 速率限制 | 防止重复调用和失控任务耗尽资源 |
| SEC16 | 紧急停止 | 管理员可阻止新操作并取消允许取消的任务 |
| SEC17 | 安全巡检 | 检查不必要端口、过宽权限和高风险配置 |
| SEC18 | 审计报告 | 输出风险、证据、整改建议和复查结果 |

### 建议的操作权限等级

- **L0 — 只读查询：** 读取指标、状态、日志和配置，不修改系统。
- **L1 — 诊断与预览：** 生成报告、配置差异和执行计划。
- **L2 — 授权变更：** 对明确的操作、目标和参数取得批准后执行。
- **L3 — 高风险操作：** 数据删除、存储重建、关键网络或权限变更须使用专门的强确认、备份和恢复流程；部分动作应禁止 AI 自动执行。

这些等级是本项目建议的安全设计，不代表 Marvis 已公开确认采用同样的分级。

| W08 | 任务锁 | 避免多个实例同时修改同一资源 |

| W10 | 通知系统 | 对重要异常发送通知 |
| W11 | 任务模板 | 提供常见运维流程模板 |
| W12 | 流程版本管理 | 记录流程变更并支持恢复 |
| W13 | 任务暂停与恢复 | 支持维护窗口和人工接管 |
| W14 | 任务模拟 | 正式执行前预览动作 |
| W15 | 工作流复用 | 将验证过的流程保存为可复用技能 |
| W16 | 任务健康监控 | 检查调度器本身是否正常 |

建议内置工作流：

- 每日 NAS 健康巡检。
- 每周安全配置审计。
- 磁盘空间不足预警。
- Docker 异常退出诊断。
- 备份完成状态与可恢复性检查。
- 证书即将过期提醒。
- 每周资源使用趋势报告。
- 指定网站或软件更新监控。
- 系统升级前检查与升级后验证。

必须区分“自动检查”和“自动变更”。空间不足可以自动扫描并告警，但不能未经授权自动删除用户数据。

## 19. 六项建议新增的 NAS 专属能力

这些能力不一定来自 Marvis 的直接功能，而是让产品真正适合 NAS 的重要差异化方向。

### 19.1 备份与恢复保障

- 检查备份是否成功。
- 检查备份完整性与可恢复性。
- 关键配置变更前检查备份状态。
- 在可行条件下执行恢复演练。

### 19.2 存储风险预警

- 综合 SMART、I/O 错误、阵列状态和温度等信号。
- 区分风险预警与确定故障。
- 不自动执行可能扩大数据损失的修复。

### 19.3 应用依赖与影响分析

- 修改网络、挂载目录或服务前识别依赖项。
- 分析变更可能影响的容器和应用。
- 在操作计划中展示影响范围。

### 19.4 配置变更追踪

- 保存关键配置快照。
- 展示变更差异、操作者和原因。
- 支持发现异常配置并恢复历史状态。

### 19.5 NAS 资源与模型调度

- 评估本地推理对 CPU、内存和加速硬件的影响。
- 在资源紧张时降低后台任务优先级。
- 优先保障存储和基础服务。

### 19.6 自动化发布与回归验证

- 统一启动入口。
- 自动构建和运行测试。
- 验证 FPK 产物与安装包结构。
- 记录版本和发布检查结果。
- 防止开发环境正常而 FPK 运行失败。

## 21. 借鉴、改造与不照搬的原则

| Marvis 产品思路 | FNOS NAS Agent 的实现方向 |
|---|---|
| 主 Agent 调度多个专业 Agent | 面向 NAS 运维任务的分工与编排 |
| 自然语言控制系统 | 通过受控工具操作 NAS 后端 |
| 智能文件管理 | 结合 NAS 目录、权限与存储容量的文件管理 |
| 系统问题诊断 | 结合系统指标、日志和历史故障分析根因 |
| 自动化工作流 | 定时巡检、备份验证、告警和修复流程 |
| 本地与云端模型 | 按隐私、资源和任务复杂度选择执行方式 |
| 技能与 MCP 扩展 | 可审计、可授权、可隔离的工具与技能体系 |
| 跨设备控制 | 安全远程管理 NAS 和多设备运维 |

不建议优先开发普通桌面软件操控、手机远控 PC 屏幕等与 NAS 核心场景关联较弱的功能。优先做好系统状态采集、故障诊断、存储安全、应用管理和可靠自动化。

## 22. 对开源项目的评估建议

腾讯官方 Marvis 与社区中受其启发的开源项目不是同一个项目。评估任何候选开源项目时，应检查：

1. 许可证是否允许预期的使用、修改和分发方式。
2. 依赖与现有 Node.js 应用的集成成本。
3. 是否能在 FNOS 环境中稳定运行。
4. 是否满足路径隔离、权限控制和执行审计要求。
5. 是否适合通过独立服务或 MCP 适配，而不是直接混入主应用。
6. 维护活跃度、测试覆盖、已知漏洞和依赖安全情况。

不能仅凭名称相似或功能介绍就认定其为腾讯官方代码，也不能假定它适合直接集成。

## 23. 最终建议

把 Marvis 当作产品设计参考，而不是技术架构模板。

推荐开发顺序：

1. **统一现有应用入口和运行环境**，确认本地启动与 FPK 实际运行逻辑一致。
2. **建立可信的系统采集、工具执行和审计底座**，确保 AI 获取真实数据且不能越权执行。
3. **实现主 Agent 与专业 Agent 的任务调度**，支持规划、并行分析、执行、验证和结果汇总。
4. **打通系统监控、故障诊断、Docker 管理和安全审批**，形成完整的 NAS 运维闭环。
5. **增加工作流、定时巡检、文件知识库和模型路由**，逐步提升自动化程度。
6. **最后扩展移动端、多 NAS 管理、MCP 与高级预测能力**。

最终目标不是得到一个“会聊天的 NAS 管理面板”，而是打造一个能够安全理解 NAS、诊断故障、执行授权操作，并通过结果验证证明任务确实完成的 AI 运维系统。
