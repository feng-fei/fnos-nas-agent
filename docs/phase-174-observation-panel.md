# Phase 174 — 工作流、运行手册与诊断证据的观察面板

## 背景

Phase 167–170 把「证据包、工作流引擎、运行手册库、只读出口」做成了后端能力，
但操作者在界面上看不到它们：概览页只有第 166 阶段的系统快照、安全巡检与模型用量
三块。运维要确认「现在有哪些巡检工作流、哪些运行手册、最近一次诊断拿到了哪些证据」，
只能去翻文档或者猜。

本阶段把这条链路补上前端一环，让观察能力出现在概览页里，而不是新开一个页面。

## 改动

### 前端

- `app/ui/index.html`：概览页新增「工作流、运行手册与诊断证据」区块，包含
  `#playbooks-refresh`（刷新按钮）、`#playbooks-status`（区块状态行）、
  `#playbooks-workflows`（工作流列表）、`#playbooks-runbooks`（运行手册列表）、
  `#playbooks-evidence`（最近诊断证据）四个容器。
- `app/ui/pages.js`：新增 `refreshPlaybooks()`，并行读取三个只读接口
  `/api/workflows`、`/api/runbooks`、`/api/diagnostics/evidence`，再分块渲染。
  进入概览页时自动调用一次，并支持按钮手动刷新。

### 渲染约束

- 三个请求并行发起，**互不阻塞**：任一接口失败只影响自己那一块，状态行给出
  「读取失败：…」的说明，其余两块照常显示。
- 全程 `textContent` 写入，不拼接 HTML；外来的文本不会被当成标记解析。
- 面板是只读的：它不下发任何动作，也不携带写操作入口。

### 测试

- `tests/phase-174-observation-panel.test.mjs`（4 用例，全通过）：
  1. 概览页存在五个容器元素；
  2. 面板读取三个只读接口且并行发起；
  3. 渲染只用 `textContent`，并且三个分块各自报告失败；
  4. 面板随概览页一起刷新，且刷新按钮已接线。

## 安全边界

- 面板只读，不新增写路径。
- 证据文本来自 `app/diagnostic-evidence.mjs`，其字段白名单与内容清洗在 Phase 167
  已经固定，本阶段不再复制一份清洗逻辑。

## 遗留

- 面板不提供「执行工作流」的入口；执行仍然只走既有的审批队列。
- 证据条目目前是英文键值对，转成中文报告需要 Phase 162 侧再做一层映射。
